# KeyRecall Scale Motor Taxonomy

**Status:** Initial formal analysis\
**Date:** August 18, 2026\
**Scope:** Derived motor structure for canonical V1 piano scale
fingerings\
**Input:** `keyrecall-scale-fingering-taxonomy.md`\
**Related:** `keyrecall-v1-domain-model.md`

------------------------------------------------------------------------

## 1. Purpose

This document derives reusable motor structure from KeyRecall's
canonical scale-fingering corpus.

The fingering taxonomy remains the source of truth for which fingers are
expected for a particular scale and hand. This document does **not**
replace that data. It asks a different question:

> Which recurring motor structures are shared by apparently different
> canonical fingerings, and how should those structures participate in
> KeyRecall's learner model?

The initial corpus contains:

-   48 scale definitions;
-   96 hand-specific canonical fingering records;
-   major, natural minor, harmonic minor, and fixed-form melodic minor;
-   multi-octave-normalized continuation behavior; and
-   one canonical fingering per scale/hand for V1.

Future alternative fingerings may map to an existing motor family or
introduce additional families. The taxonomy therefore describes the
current canonical corpus, not the universe of legitimate piano
fingering.

## 2. Separation of Concerns

Three layers must remain distinct:

``` text
CanonicalFingering
    exact expected fingers for a scale/hand
             |
             v
MotorRealization
    derived family + orientation + phase + boundaries + geometry
             |
             v
TechnicalEvent
    observable transitions generated by an exercise
```

### 2.1 CanonicalFingering

Authoritative pedagogical data.

``` text
FingeringPattern
    hand
    direction
    entry
    cycle
    terminal_override
```

A learner is scored against this layer in V1.

### 2.2 MotorRealization

A structural interpretation of a canonical fingering.

A realization should be derivable rather than independently
hand-authored:

``` text
MotorRealization
    family
    orientation
    phase
    entry_behavior
    terminal_behavior
    geometry_signature
```

### 2.3 TechnicalEvent

A concrete event encountered while executing a generated exercise.

Examples include a thumb-under crossing, finger-over crossing, boundary
entry, terminal substitution, or turnaround. Technical events provide
more specific evidence than family membership alone.

## 3. Analysis Principles

The motor taxonomy follows several constraints.

1.  **Canonical fingering remains authoritative.** Motor-family
    classification must never generate or silently alter canonical
    fingering.
2.  **Rotation is not a new family.** If two continuation cycles differ
    only by cyclic phase, they share the same abstract cycle.
3.  **Hand mirroring is modeled explicitly.** RH and LH may be
    orientations of a common higher-order family without pretending that
    their physical execution is identical.
4.  **Boundary behavior is not cycle identity.** Entry and terminal
    adaptations do not create a new motor family by themselves.
5.  **Keyboard geometry matters.** Identical finger-number cycles can
    impose meaningfully different physical demands on white and black
    keys.
6.  **Scale topology is separate.** A change from natural to harmonic
    minor can preserve the motor realization while changing the pitch
    task.
7.  **Alternative fingerings remain extensible.** Future alternatives
    may add realizations or families without changing the V1 canonical
    records.

## 4. Fundamental Three/Four-Finger Structure

The completed fingering audit strongly supports a common diatonic scale
motor concept based on alternating groups of three and four fingers.

For RH ascending, the dominant continuation structure can be represented
canonically as:

``` text
1 2 3 | 1 2 3 4
```

or as the seven-position cycle:

``` text
[1, 2, 3, 1, 2, 3, 4]
```

The corresponding LH ascending orientation is its reversal:

``` text
4 3 2 1 | 3 2 1
```

``` text
[4, 3, 2, 1, 3, 2, 1]
```

The tonic can occur at any phase of these cycles. Consequently, familiar
"CAGED," flat-key, and black-key fingerings often differ primarily in
where the scale begins relative to the recurring three/four-finger
structure.

## 5. Proposed MotorFamily Hierarchy

The initial formal taxonomy is:

``` text
DIATONIC_SCALE_MOTOR
|
+-- THREE_THEN_FOUR
|   +-- RIGHT_ASCENDING
|   `-- LEFT_ASCENDING
|
`-- FOUR_THEN_THREE
    `-- RIGHT_ASCENDING
```

This hierarchy intentionally separates two levels.

### 5.1 `DIATONIC_SCALE_MOTOR`

The broad parent concept: fluent execution of seven-note scalar motion
through alternating thumb crossings and three-/four-finger groups.

This is a useful learner-model parent but is too broad to be the only
motor component.

### 5.2 `THREE_THEN_FOUR`

The dominant V1 family. Its RH canonical cycle is:

``` text
[1, 2, 3, 1, 2, 3, 4]
```

and its LH ascending orientation is the reversal:

``` text
[4, 3, 2, 1, 3, 2, 1]
```

Most canonical V1 scale fingerings appear to be rotations and boundary
variants of this family.

### 5.3 `FOUR_THEN_THREE`

The exceptional ordering used by the selected RH canonical fingering for
C-sharp and F-sharp fixed-form melodic minor:

``` text
1 2 3 4 | 1 2 3
```

Canonical cycle:

``` text
[1, 2, 3, 4, 1, 2, 3]
```

The observed tonic-relative realization `23123412` corresponds to a
rotation of this cycle.

This is not an unrelated technique. It is the opposite ordering of the
same three-/four-finger grouping concept. For learner modeling it should
therefore be a sibling under `DIATONIC_SCALE_MOTOR`, not an unrelated
skill.

## 6. Phase as a Derived Property

A phase identifies where a scale tonic lies within the abstract cycle.

For a canonical cycle:

``` text
THREE_THEN_FOUR / RH
index:  0 1 2 3 4 5 6
finger: 1 2 3 1 2 3 4
```

a tonic-relative continuation can be represented by a rotation rather
than a separately learned motor family.

For example, rotations include:

``` text
phase 0: 1 2 3 1 2 3 4
phase 1: 2 3 1 2 3 4 1
phase 2: 3 1 2 3 4 1 2
phase 3: 1 2 3 4 1 2 3
phase 4: 2 3 4 1 2 3 1
phase 5: 3 4 1 2 3 1 2
phase 6: 4 1 2 3 1 2 3
```

The exact numeric phase convention should be generated from canonical
cycle data and covered by tests. Human-readable scale labels should not
be encoded into the family identifier.

This gives a useful decomposition:

``` text
canonical fingering
    =
motor family
    + hand/orientation
    + cycle phase
    + entry behavior
    + terminal behavior
    + keyboard geometry
```

## 7. Why Phase Should Not Become a Separate Learner Skill

Phase is important for exercise generation and diagnostic description,
but a learner should not necessarily have seven independent latent
"phase skills."

The motor act of executing the same three/four cycle from a different
tonic phase is strongly related. KeyRecall should initially treat phase
as a contextual feature that modulates evidence for the parent motor
family and for the technical events actually encountered.

If telemetry later demonstrates persistent phase-specific difficulty,
the learner model can introduce phase-sensitive parameters without
changing the fingering domain model.

## 8. Boundary Adaptation

Entry and terminal behavior are orthogonal to recurring cycle identity.

Examples already established in the fingering research include:

-   C-major RH uses an internal tonic finger suitable for continuation
    but substitutes finger 5 at the final upper tonic.
-   B-flat major RH begins with finger 2 even though an internal B-flat
    occurs at a different phase/finger.
-   E-flat natural and harmonic minor can share recurring structure
    while differing at an entry boundary.

Boundary behavior should therefore be modeled as technical evidence
rather than as a reason to split motor families.

Candidate boundary concepts:

``` text
ENTRY_ALIGNMENT
CONTINUATION_BOUNDARY
TERMINAL_SUBSTITUTION
TURNAROUND
```

These names are provisional until the technical-event pass.

## 9. Keyboard Geometry Is an Independent Axis

Finger-number equivalence does not imply identical physical difficulty.

A transition should retain the physical key classes involved:

``` text
WHITE -> WHITE
WHITE -> BLACK
BLACK -> WHITE
BLACK -> BLACK
```

and, where useful, more detailed geometry such as:

-   thumb on white versus black key;
-   long finger on black key;
-   crossing into or out of a black-key group;
-   two-black-key versus three-black-key region;
-   semitone versus whole-tone lateral displacement; and
-   octave-boundary location.

Thus B major, D-flat major, and G-flat/F-sharp-related patterns may
share a motor cycle while still providing non-identical evidence because
their keyboard geometry differs.

`MotorFamily` captures recurring organization; `TechnicalEvent` captures
the concrete realization.

## 10. Direction and Hand

V1 fingering research supports generating descending fingering by
reversing the complete ascending finger stream for the fixed pitch
collection.

That does **not** mean ascending and descending should be treated as
identical observations in the learner model.

A crossing reverses physical role:

``` text
RH ascending:  thumb-under / finger-over relationships
RH descending: corresponding reversed motion
```

Likewise, LH is not merely "RH backwards" from the learner's
perspective. Hand independence, asymmetry, and coordination remain real
skills.

Recommended structure:

``` text
MotorFamily
    abstract grouping organization

MotorRealization
    hand
    direction
    phase
    geometry
```

The parent family can transfer evidence across realizations while
hand/direction-specific technical events retain diagnostic resolution.

## 11. Initial Mapping Result

At the current level of analysis, the 96 canonical V1 hand records do
**not** imply 96 motor families.

The working result is:

  -----------------------------------------------------------------------
  Family                              Canonical V1 use
  ----------------------------------- -----------------------------------
  `THREE_THEN_FOUR`                   Dominant family across major,
                                      natural minor, harmonic minor, and
                                      most fixed melodic minor fingerings

  `FOUR_THEN_THREE`                   C# and F# fixed melodic minor RH
                                      canonical fingering

  `DIATONIC_SCALE_MOTOR`              Parent concept shared by both
  -----------------------------------------------------------------------

The exact per-record phase table should be generated mechanically from
the canonical fingering dataset rather than transcribed manually into
this document. That generated mapping is the next analysis artifact.

## 12. TechnicalEvent Model

A technical event should describe an observed or expected local motor
demand.

Proposed representation:

``` yaml
TechnicalEvent:
  hand: RIGHT
  direction: ASCENDING

  transition:
    from_finger: 3
    to_finger: 1

  role: INTERNAL_CROSSING

  geometry:
    from_key_class: WHITE
    to_key_class: WHITE
    interval_semitones: 2

  structural_context:
    motor_family: THREE_THEN_FOUR
    phase_before: 2
    octave_boundary: false
```

Not every adjacent finger transition deserves an independent learner
component. The event representation should be rich enough to support
aggregation at several levels.

## 13. Candidate Event Classes

The first technical-event derivation should distinguish at least:

``` text
ORDINARY_ADJACENT
THUMB_UNDER_3
THUMB_UNDER_4
FINGER_3_OVER_THUMB
FINGER_4_OVER_THUMB
ENTRY_ALIGNMENT
OCTAVE_CONTINUATION
TERMINAL_SUBSTITUTION
TURNAROUND
```

The exact event names should be hand/direction neutral where possible.
For example, a more abstract implementation may encode:

``` text
CROSSING
    crossing_finger: 3 | 4
    thumb_role: UNDER | OVER
```

rather than creating four unrelated event types.

That choice should be made after enumerating all events produced by the
96-record corpus.

## 14. Relationship to the Q-Matrix

The motor taxonomy suggests that scale exercises should not map only to
whole-scale skills such as:

``` text
C_MAJOR_RH
F_SHARP_HARMONIC_MINOR_RH
```

Those remain useful task identities, but they are poor latent motor
components by themselves.

A generated exercise can instead provide evidence for multiple
components:

``` text
exercise
  |
  +-- pitch/topology components
  |
  +-- DIATONIC_SCALE_MOTOR
  |
  +-- THREE_THEN_FOUR or FOUR_THEN_THREE
  |
  +-- hand/direction realization
  |
  +-- crossing technical events
  |
  +-- boundary/turnaround events
  |
  `-- geometry-conditioned execution
```

This allows competence learned in one scale to transfer to another
without treating the two scales as identical.

## 15. Q-Matrix Weighting Principle

The Q-matrix should distinguish **presence** from **diagnostic
strength**.

An exercise may contain many repetitions of a common motor family but
only one instance of a difficult `4 -> 1` crossing. The latter can be
more diagnostically informative than its raw event count suggests.

Initial weights should therefore be informed by:

-   number of opportunities;
-   event difficulty/specificity;
-   correctness;
-   timing stability;
-   repeated-error localization;
-   hand and direction;
-   tempo;
-   octave count; and
-   prior uncertainty in the learner component.

These weights belong to the learner-model design, not the fingering
taxonomy.

## 16. Transfer Model

The hierarchy supports graded transfer.

For example, successful C-major RH practice can update:

``` text
DIATONIC_SCALE_MOTOR
THREE_THEN_FOUR
RH_ASCENDING_REALIZATION
3-finger crossing events
4-finger crossing events
C-major pitch/topology knowledge
```

Later practice of A harmonic minor can reuse evidence for the first
several components while still testing different pitch topology and
keyboard context.

C# fixed melodic minor RH can share evidence at `DIATONIC_SCALE_MOTOR`
while separately exercising `FOUR_THEN_THREE`.

This avoids both extremes:

-   treating every scale as independent; and
-   assuming motor fluency transfers perfectly across all scale
    contexts.

## 17. Alternative Fingerings

The model must support future alternatives without changing the family
definitions or canonical V1 scoring policy.

``` text
ScaleHand
   |
   +-- CanonicalFingering ----+
   |                          |
   `-- AlternativeFingering --+--> MotorRealization --> MotorFamily
```

An alternative may:

1.  map to the same family and phase;
2.  map to the same family at a different phase;
3.  use different boundary behavior;
4.  produce different keyboard-geometric events; or
5.  introduce a genuinely new motor family.

Therefore the relationship is:

``` text
FingeringPattern -> MotorRealization
```

not:

``` text
Scale -> MotorFamily
```

## 19. Taxonomy Status

### Established from the canonical fingering research

-   canonical fingering and derived motor structure are separate;
-   the dominant diatonic pattern alternates three- and four-finger
    groups;
-   many tonic-relative patterns are cyclic rotations of the same
    continuation structure;
-   RH and LH expose mirrored/reversed orientations;
-   entry and terminal behavior must remain separate from cycle
    identity;
-   keyboard geometry must remain available to the technical-event
    layer;
-   C# and F# fixed melodic minor RH use the selected opposite 4+3
    grouping; and
-   future alternative fingerings must not require redesigning the
    model.

### Working hypotheses to test mechanically

-   every canonical V1 record can be classified under
    `DIATONIC_SCALE_MOTOR`;
-   every record except C#/F# fixed melodic minor RH belongs to
    `THREE_THEN_FOUR`;
-   C#/F# fixed melodic minor RH are the only canonical V1
    `FOUR_THEN_THREE` realizations;
-   phase plus boundary behavior is sufficient to distinguish exact
    finger-number realizations within a family; and
-   no third canonical V1 motor family is required.

## 20. Next Analysis Pass

The next pass should be computational rather than another manual
fingering survey.

Build a machine-readable table containing all 96 canonical records and,
for each:

``` text
scale
form
hand
canonical entry
canonical continuation cycle
terminal override
motor family
orientation
phase
```

Then mechanically:

1.  canonicalize cycles under rotation;
2.  verify family membership;
3.  enumerate distinct phases;
4.  enumerate boundary variants;
5.  generate all ascending and descending technical transitions;
6.  attach keyboard geometry from the actual scale spelling/MIDI keys;
7.  count distinct event signatures;
8.  identify which event distinctions are pedagogically meaningful
    enough to become learner components; and
9.  produce the complete scale/hand -\> realization mapping table.

If a canonical record fails to fit the proposed two-child hierarchy, the
data should force a taxonomy revision rather than being coerced into the
nearest family.

## 21. Document Status

This is the first formal motor-analysis specification.

It establishes the proposed hierarchy and the rules by which the
complete canonical fingering corpus should be analyzed. It deliberately
does **not** claim that the two-family result is final until all 96
records have been normalized into a machine-readable analysis table and
verified mechanically.

The immediate next artifact should therefore be that complete mapping
and verification pass. Once verified, this document can be revised from
a proposed taxonomy into the V1 motor taxonomy.

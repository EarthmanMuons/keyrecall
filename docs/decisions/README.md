# Decisions

Why KeyRecall is shaped the way it is, and what we ruled out.

Grouped by durable subject rather than one file per choice, so the directory
stays a small set of things you can read rather than a ticket archive. Inside
each file, every decision has the same four parts:

**Decision** what we do. **Why** the reasoning. **Evidence** what supports it,
and how strongly. **Consequences** what it costs, and what it forecloses.

Read one when you are about to change the thing it describes. If a decision here
disagrees with the code, the code is what happens and the decision is stale; say
so rather than assuming the code is wrong.

describes something not built; a `superseded` one is kept because a finding in
it outlived the decision itself.
